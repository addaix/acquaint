acquaint.refresh#

Is a record built from someone’s own writing due for a refresh? Per-corpus watermarks against what is newer.

A record mined from a corpus (an operator’s positions from what they typed to their agents, say) goes stale as the person keeps writing. Its sources.md holds one watermark per corpus (the newest item mined), and its refresh log. This module counts, per corpus, how many items are newer than the watermark, and says whether a refresh is due: the last refresh is older than max_age_days, or a corpus count has reached its threshold. It only reads; the refresh itself stays a reviewed pass.

Which corpora a record uses is per-record configuration, refresh.toml beside sources.md (it lives in the private store, so paths there may be machine paths):

max_age_days = 7                      # default 7

[corpus.questions]
kind = "json-folder"                  # a sourcer name, see SOURCERS
path = "~/.local/share/example/questions"
items = "exchanges"                   # the list of records inside each JSON file
field = "asked_at"                    # each record's timestamp
watermark_row = "question store"      # the row of the watermark table in sources.md
threshold = 100                       # default 100; 0 reports the count, never triggers

[corpus.overrides]
kind = "jsonl"
path = "~/.local/share/example/overrides.jsonl"
field = "at"
threshold = 10                        # no watermark_row: counted since the last refresh
missing_ok = true                     # absent file = nothing yet (else it is unchecked)

Other keys: watermark_where (text the row’s Where cell must contain, when several rows share a corpus name), pattern (a glob, for the folder sourcers). Paths take ~ and $VARS and must be absolute. Times without a zone are UTC, and so is a date-only watermark’s day.

Why a separate TOML file rather than a block inside sources.md: sources.md is rewritten by every refresh (its candidate replaces the installed one), so a machine block in it would be at the mercy of that rewrite; the corpus list changes rarely and is edited by hand. The watermarks themselves stay in sources.md, the one place a refresh moves them, read from its watermark table (a Markdown table under a heading containing “Watermark”, with columns Corpus, Where and Watermark; the first ISO date or time in the Watermark cell is the watermark). The last refresh is the latest date that opens an item of the list under the “Refresh log” heading.

A watermark that is a date only means “everything through that day was read”; a time is taken as given. A corpus is a sourcer: a factory taking the corpus’s TOML table and returning count_since(watermark) -> int. SOURCERS holds the generic ones (a JSONL file, a folder of JSON files, a folder of files by modification time); a host adds its own through the sourcers argument of refresh_status().

Whether a refresh is due, from a record’s sources.md and refresh.toml texts.

Returns {"outcome", "due", "reasons", "age", "corpora", "unchecked", "configured"}. outcome is due (some trigger fired), not_due (none fired and everything was checked) or unchecked (none fired, but something could not be checked, so “not due” cannot be claimed). age is the last refresh against max_age_days; each corpus row has its watermark (and where it came from), the count newer, its threshold and whether it triggers. A corpus that could not be counted goes to unchecked with the reason, never silently to zero, and never takes the others down with it.

Return type:

dict
